## Goal
Implement roadmap T-0243: returning-user boot routing, guarded screen transitions, Android Back
and pending Toast delivery. Keep screen content in T-0244–0246. Reconcile merged prerequisite statuses.

## Context
- docs/ARCHITECTURE.md#boot-and-navigation: returning players enter Home from journey_slot.
- docs/DESIGN.md#flow-returning-user: no popups; pending results appear as Toasts.
- PRODUCT FR-PLAT-04: Sheet first; Level -> unlocked Home, otherwise background; Home -> background;
  elsewhere one screen back. Save before background; never an exit dialog.

## Current state
Main d89b11a merged T-0242. Nav has typed Screen enum, synchronous P1 start/go_home/go_to_level,
factory injection, mounting and debug routing; boot.gd starts it. Level owns a local P1 Progress,
and reconfigures that owner on each mount. Home/Journey/Postcard scenes do not exist yet.
Sheet handles native Back independently; Toast is viewport-scoped with replacement and visibility.
Save emits backup_restored and exposes committed_view/flush/writes_blocked. No background adapter
exists. Godot4.7's built-in AndroidRuntime.getActivity exposes Activity.moveTaskToBack(boolean).
T-0242 intentionally did not integrate gameplay economic providers; Nav must not enable partial
atomic gameplay or invent provider grants. P1 tests remain unchanged through explicit Nav P2 mode.

## Specification
1. Add Nav.configure_p2(background:Callable=Callable(),animate:bool=true)->Error enabling navigation
   only before its first boot; repeated configuration is inert OK. Host exit releases native Back ownership
   and cancels transitions so remount/restart works. Boot scene calls it explicitly. Nav start selects Home using the unclamped
   committed saved current slot >= configured journey threshold; otherwise Level with existing content
   clamping. Guard reentrant routes throughout Save/Config/Content loading. Invalid/departed hosts
   reject routes/Back and retain pending Toasts until a valid restart. Save/Config/Content errors leave BOOT, with no premature screen/effects. P1 injection stays
   available. Replacing configured service identities resets P2 mode/screen/history and removes
   native Back ownership; configure ignores replacement during a guarded transition. Repeated
   same-identity injection preserves mode. No Progress/Economy activation, save format, balance, SDK or boot monetization changes.
2. Add go_to_screen(screen:Screen)->Error for non-BOOT/non-LEVEL/non-DEBUG destinations, guarded
   history of screen+slot, home_unlocked()->bool, handle_back()->Error. Repeated same destinations
   are inert. P2 go_home rejects before unlock; existing P1 routes stay compatible. Missing future
   scenes remain empty states. Level debug routing remains debug-gated.
3. Before leaving Level or backgrounding, call its new prepare_navigation()->Error to synchronously
   persist/retry its actual current board through its existing Progress APIs; then Save.flush. Reject
   busy/failed persistence and preserve current screen/history/mounted node. Diagnostic/historical
   Level does not overwrite campaign. Native Android background uses a small service-owned platform
   adapter calling built-in AndroidRuntime.getActivity().moveTaskToBack(true); desktop is unavailable.
   Injected background Callable returns Error, called only after successful persistence/flush.
4. Back first consults same-viewport Sheet.handle_back, including busy/non-dismissible. Sheet's native
   notification defers ownership to a same-viewport active Nav P2 group, avoiding double navigation
   regardless of notification traversal order; standalone component behavior stays unchanged.
   Level routes Home when unlocked, otherwise backgrounds; recheck the threshold after a successful
   pending completion retry. History destinations revalidate current Content, preserving history
   and screen when no longer available; Home backgrounds; other screens pop one
   history entry (fallback Home or current campaign Level). BOOT/busy transition fails safely. Nav
   owns native GO_BACK and unhandled ui_cancel; no quit or custom confirmation path.
5. P2 route transitions kill/release owned tweens on reset/exit; block reentrant routing under an
   explicit busy state. Out uses FAST/IN fade; in BASE/OUT alpha+Space.L slide, reduced motion immediate.
   Mounted Controls temporarily disable input/process during transitions and restore previous mode.
   screen_changed retains mount-before-notify and low-processor state; append transition_finished.
   Reentrant callbacks cannot discard newly mounted screens. Non-Control/empty scenes work normally.
6. enqueue_toast(key:String,variant:StringName=&"info")->Error validates key/variant, deduplicates
   pending identical pairs; one reusable Nav-owned Toast on Home drains FIFO as each hides. Keep
   pending messages across boot errors/routes, hide when leaving Home, and consume only successful
   presentation. Attach the reusable Toast to the mounted Home Control for inherited theme/safe
   body bounds; park it hidden in Nav's layer before screen disposal. Connect/disconnect Save.backup_restored; queue nav.toast.backup_restored before boot
   delivery. nav.toast.purchases_restored is available for future explicit provider delivery, with no
   IAP call. Toast container is passive; no new UI component/theme/token/global singleton.
