## Goal
Upgrade CI v1 so every pull request gets blocking task-scope, task-metadata and test-count checks
before T-0023 turns those check names into branch-protection requirements.

## Context
- `docs/design-pass/07-git-pr-merge.md` §5 requires `scope`, `tasks-lint` and `test-count` on
  every PR.
- T-0020 provides `tools/check_scope.py`; T-0019 provides `tools/tasks.py lint`; T-0021 provides
  `tools/count_tests.py`.
- T-0018 provides the existing `.github/workflows/ci.yml` and its format, lint, Godot, pipeline and
  tools jobs.

## Current state
- `.github/workflows/ci.yml` runs on every pull request and pushes to `main`.
- Existing jobs use `ghcr.io/krystiangaleczka-tech/world-of-words-toolchain:latest`.
- `tools/check_scope.py` resolves task identity from `GITHUB_HEAD_REF`, validates the task file and
  compares changed paths against `touch`.
- `tools/count_tests.py` compares committed test definitions against `GITHUB_BASE_REF` and reads
  the exact `test-count-exception` label from `GITHUB_EVENT_PATH`.
- T-0018 and T-0021 are merged and marked `done`.

## Specification
### Behavior
1. Add a CI job named exactly `scope`.
2. On pull requests, `scope` checks out enough Git history to resolve the base branch and runs
   `uv run python tools/check_scope.py`.
3. On pushes to `main`, the `scope` job stays present but prints an explicit SKIP message instead
   of trying to resolve a task branch.
4. Add a CI job named exactly `tasks-lint` that runs `uv run python tools/tasks.py lint` on both
   pull requests and pushes to `main`.
5. Add a CI job named exactly `test-count`.
6. On pull requests, `test-count` checks out enough Git history to resolve the base branch and runs
   `uv run python tools/count_tests.py`, preserving access to `GITHUB_EVENT_PATH` for the label
   exception.
7. On pushes to `main`, the `test-count` job stays present but prints an explicit SKIP message.
8. All three jobs run in the same pinned GHCR toolchain container and use the same package
   credentials pattern as CI v1.
9. Existing format, lint, Godot, pipeline and tools jobs keep their current behavior.
10. Failure output must remain readable: the invoked tools' `OK:` / `ERROR:` output is visible
    directly in the job log.

### Edge cases
| Case | Expected |
|---|---|
| PR from `t/0022-*` | `scope` resolves T-0022 and passes only for files in this task's touch list |
| PR with malformed task metadata | `tasks-lint` fails |
| PR that removes tests | `test-count` fails unless the exact exception label is present |
| push to `main` | `scope` and `test-count` report explicit SKIP; `tasks-lint` still runs |
| shallow checkout would hide `main` | avoided by full-history checkout for comparison jobs |
